# 第一阶段：SW6306V 电源控制台

寄存器依据：用户提供的《SW6306V_寄存器手册_V1.0.2.pdf》，第 5–11、16–19、25、35–37 页。
显示目标为现有 1024×600 屏幕。当前界面已中文化，使用完整 Noto Sans SC 常规字库，
正文 16 px，标题/主要数值 24 px；字体文件和说明见 main/ui/fonts/。

## 已接入页面

| 页面 | 内容 |
| --- | --- |
| Monitor | 二级界面：“功率监控”显示 BUS 电压、电流、功率及最近 60 个有效 ADC 采样曲线；“电量计”直接显示 REG0x86–0x8C、0x94、0x99 的容量、电量与原始值，不做软件估算 |
| Output | 板内 VBUS 强制输出使能、22V 草稿快捷按钮、共享 IBUS 强制控制、输出电压、输出和充电 IBUS 限流、实时总线/Die 温度 |
| Buck-Boost | 频率、共享峰值限流、Die 过温门限、M2 RDS(on)、轻载强制 PWM |
| System | 亮度、C1 的 DRP/Try.SRC、Source、Sink；保留顶部下拉亮度面板 |
| Fault Analysis | 只读显示 REG0x15 事件与 REG0x2A–0x2C 的充放电异常历史、62368/DPDM/CC 保护状态和原始寄存器值 |

配置页首次进入时后台读取芯片。读取成功后才能编辑，右侧显示最后一次回读值。
点击数值打开固定小数输入键盘，Clear 清空、退格删除、Cancel 放弃、Use value 写入草稿。
范围和步进均强制检查，不自动舍入。数字输入不会立即写芯片。
Reload 重新读取；有未应用草稿时需确认覆盖。Discard draft 恢复最后一次回读值。
Apply 写入并回读，失败后显示错误码及未知状态，必须重新 Reload。
页面对象长期保留，切页不会销毁对象、丢失草稿或产生悬空定时器指针。

Buck-Boost 的 Reset values to draft 载入手册复位值：300 kHz、18 A、120℃、10 mΩ、PFM。
它只改草稿，不代表这些值适合用户实际电路，仍需 Apply 才生效。

## 第一阶段字段映射

| 参数 | 寄存器/位 | 应用值 |
| --- | --- | --- |
| 强制 VBUS 输出 | 0x40[0]、0x28[3]、0x22 | 应用开启：设置电压并启动放电；应用关闭：清除强制电压并保持物理输出关闭 |
| 强制 IBUS | 0x40[6] | 同时控制充电、放电 IBUS |
| 输出电压 | 0x41、0x42[3:0] | 3300–27300 mV，10 mV/step |
| 输出 IBUS | 0x43[7:0] | 200–7000 mA，50 mA/step |
| 充电 IBUS | 0x49[7:0] | 200–7000 mA，50 mA/step |
| 开关频率 | 0x114[7:6] | 编码 0/1/2/3 = 300/200/400/500 kHz |
| 充放电峰值限流 | 0x114[5:4] | 12/14/16/18 A，共用一个档位 |
| Die 过温门限 | 0x114[3:2] | 120/130/140/150℃ |
| M2 RDS(on) | 0x115[7:6] | 2.5/5/7.5/10 mΩ，与峰值限流联动 |
| 轻载模式 | 0x116[6] | 0：PFM；1：强制 PWM |

未提供手册不存在的 Buck/Boost/Auto 工作模式单选项，也没有虚构独立的充电/放电峰值寄存器。
IBUS 限流和开关峰值限流是不同参数，界面分别呈现。
只更新指定掩码，保留所有其他位；尤其 0x116 的 NTC、62368、恒温环设置不会被 PWM 开关覆盖。
读取输出配置时按照手册将寄存器值钳位到物理范围，例如复位原始值 0 显示为 3.300 V/0.200 A。
右侧这些值表示强制设定值，不表示协议协商结果或 ADC 实测值。

## 写入语义及实机验证边界

本页按实际接线控制板内 VBUS，负载不经过 USB 端口。界面的“强制 VBUS 输出使能”
是输出命令：开关打开并应用后主动启动放电；开关关闭并应用后保持物理输出关闭。
手册描述的强制电压控制适用于系统控制模式，不新增未记载的芯片运行模式切换。
右侧“电压强制控制”仅是 REG0x40[0] 的回读，不等于放电/通路实测状态。

电压的两个字节分别立即生效，手册未提供原子提交/锁存命令。
每次应用输出配置时，驱动先检查充电状态和端口连接状态；检测到充电输入时拒绝操作。
本板两个 A 口被识别为不存在，使用 C1 作为放电触发。启用时驱动在确认输出关闭后自动将 C1 设置为
Source（REG0x132[1:0]=1）并回读确认，拒绝 A1/A2/C2 的其他输出连接。不要接普通 USB 设备测试强制高压。
应用结束后同步系统页的实际角色；已有角色草稿保留。关闭输出不会恢复之前的 C1 角色。
具体顺序为：置 REG0x28[3]=1，轮询 REG0x18[4:0] 确认放电及全部通路关闭；
启用时设置并校验 C1 Source；随后置 REG0x40[0]=1，并写入、回读 0x41 与 0x42[3:0]。
两个字节写完后设置最终 VBUS/IBUS 使能位，再整体回读电压、使能和已启用的限流值。
启用时校验成功后清零电压补偿、禁止 C1 空载检测，再清除 REG0x28[3]，等待 C1 Source 连接并触发放电。
关闭时保留 REG0x28[3]=1，不触发放电。
整个过程使用现有递归寄存器锁，与后台采样串行；不依赖强制使能关闭时预写是否生效。

手册没有独立的裸 VBUS/转换器开启命令。C1 Source 插入事件 REG0x22[6] 有明确前提：
只有 Source 连接态才有效。因此解除输出关闭后先等待 REG0x1D[7]=1，且其他 C 口连接位为零，
最长等待 3 秒；成功后才向 REG0x22 写 0x40。事件寄存器直接写入，不读改写、不校验自清零位。
设置 Source 角色只配置了连接方向，不能模拟 CC 上的受电端 Rd；C1 的 CC 悬空时不能靠此方案启动。
这不要求先完成 PD 电压协商，但仍需要有效的 Type-C 受电端连接/CC 测试连接。
超时返回 ESP_ERR_NOT_FOUND，界面提示检查 CC/Rd，串口输出 REG0x19、REG0x1D 用于诊断，
随后尝试保持输出关闭。I2C 错误保留原错误码，不当作连接缺失处理。
REG0x118[3] 置 1 禁止 C1 的空载检测，防止板内负载未经过 USB 通路而触发空载关断。
这只屏蔽空载检测，不保证 CC 拔出后仍维持放电。C1 通路也会被打开，连接器会输出强制设定的高压。
REG0x101 低四位设为 0x5，固定电压偏移和线补均为零；其他位保留。
关闭输出不会恢复这些补偿/空载设置，它们是本次板内供电配置的一部分。
关闭确认、开启确认均使用 1 秒软件超时。开启后要求 REG0x18 显示放电打开、仅 C1 通路打开、
充电关闭；CC 重新连接和放电启动的实际行为及这些软件超时是否充足，仍需实机验证。

根据手册，写 0x43/0x49 时需要先使能共享 IBUS 强制位。应用过程中旧的限流值可能短暂生效。
因此输出应用窗口会列出两路限流和输出中断说明。第一次验证使用匹配的测试负载。
IBUS 开关关闭时，不会为了保存限流数字而短暂打开强制限流；未应用的限流数字不写入芯片，
应用成功后以重新读回的数值刷新页面。

多个寄存器的应用不是硬件事务。中途失败可能已经写入部分字段，不自动回滚或重试。
如果已经进入输出关闭流程，失败时尝试维持 REG0x28[3]=1；通信故障可能使关闭状态无法确认，
串口会记录失败阶段及再次置位关闭的结果。页面标记状态未知，重新读取后才能再次应用。
即使没有草稿差异也允许重新应用，以明确执行开启、关闭或失败后的恢复。
成功提示只代表寄存器回读匹配，不代表输出电压、电流或温度门限已做实测验证。
范围是芯片手册范围，不能替代对实际电源板、负载和 M2 参数的确认。

## 强制输出 22V 验证

1. 将能承受 22V 的测试负载接到板内 VBUS/GND，断开充电输入和其他端口设备。
   开启时软件自动将 C1 设为 Source；C1 的 CC 必须接有有效的受电端/Rd 测试连接。
   测试连接的电源侧必须能承受 22V，不能用手机等普通设备充当连接触发。
2. 进入“输出控制”，读取成功后点击“载入 22V”：它把电压草稿设为 22.000V，并打开强制电压草稿开关。
3. 此按钮保留原有 IBUS 设置，只修改草稿；点击“应用输出配置”并确认后才写入芯片。
4. 串口标签 `sw6306_output` 应报告 `Internal VBUS ON, target=22000 mV, trigger=C1`。寄存器应为
   REG0x40[0]=1、REG0x41=0x98、REG0x42[3:0]=0x8，其他位保留。
   成功或失败时串口逐项打印 REG0x18/19/1D/28/40/41/42/2A/2B/2C；读取失败则打印原始错误并停止诊断读取。
   失败时先尝试关闭输出，再读取诊断寄存器；不会为诊断重新触发插入事件，以保留异常历史。
5. 核对实时总线 ADC 和万用表；等待超过原来的空载关断时间，确认板内输出持续。功率、
   IBAT 限流和保护配置保持原有设置，若压降或关断需查异常，不通过关闭保护规避异常。
6. 关闭“强制 VBUS 输出使能”并应用，确认放电关闭。VBUS 电容放电有延迟，不保证瞬时降到零。
7. 若提示 `C1 has no Source attachment`，检查 CC 接线以及日志中的 REG0x19/REG0x1D。
   如果要求 C1 的 CC 完全悬空也能开启裸 VBUS，这份手册未提供可确认有效的控制方法，
   需要厂家补充独立转换器启动说明，或结合原理图调整连接检测电路。
8. 本次不做上电自动输出 22V；由界面显式应用，之后可在 3.300–27.300V 范围内修改目标电压。

## 异常分析模块

异常分析页面每 200ms 读取 REG0x15、REG0x2A、REG0x2B、REG0x2C，并通过独立的
数据快照组传给 UI。页面不写任何异常寄存器：REG0x15 的事件位按手册属于写 1 清零，
所以自动清除会丢失故障证据。REG0x2A–0x2C 中的保护位表示“发生过异常”，通常在下次
开机事件时才清零，界面将其标为异常历史而不误报为实时故障。按键和场景变化事件只作
状态提示，不计为充放电保护异常。

## 四层关系及扩展点

| 层 | 对应代码 | 职责 |
| --- | --- | --- |
| UI | ui_page_manager / ui_* 页面 / ui_numeric_input / ui_common | 导航、控件、草稿编辑、结果提示 |
| 状态与模型 | config/、data_snapshot | 已读回配置、草稿、参数物理单位/合法范围、实时数据副本 |
| 服务 | sw6306_config_service / sw6306_config_worker / data_service | 业务验证、应用及回读、后台队列 |
| 驱动 | sw6306_power_config / register_access / 其他芯片驱动 | 寄存器编码、掩码读改写、I2C 和递归事务锁 |

config/sw6306_power_types.h 是跨层共享的纯数据契约，不包含 I2C 或 LVGL；驱动、服务和模型共享这些物理量类型。
配置任务使用请求/结果两个长度为 1 的队列，消息是值副本，不携带 LVGL 对象指针。
UI 轮询结果时只合并对应配置组，不覆盖其他页面的草稿。采集任务和配置任务共用寄存器递归锁，防止页面选择串扰。
配置结果更新配置模型；ADC 数据仍由采集任务更新，不将设定值伪装成实测值。

增加下一组参数时，依次扩展纯数据类型/合法范围、驱动读写、服务 load/apply、后台 operation，
最后增加页面或现有页面中的控件。新数值参数可复用 sw6306_numeric_spec_t 和 ui_numeric_input_open。
页面和服务应按组扩展，避免全局 Apply 将其他页面尚未确认的修改一起写入。

本阶段没有 NVS 保存/启动自动恢复新配置。保留原工程的固定 startup_config 行为；
MCU 重启后页面重新读取芯片，芯片自身未掉电时可能保留此前设置。

## 编译前检查与后续实机核对

tools/check_phase1_static.py 检查 CMake 源文件清单、C 语法结构、LVGL 调用名和参数数量、
所需控件/字体开关及 UI/寄存器边界。语法检查使用 pycparser 和外部类型占位声明，
不是编译器类型检查，不验证预处理、链接、RAM 使用或实机显示布局。

本次按要求停在编译前，没有运行 idf.py build、固件烧录或硬件读写测试。
用户后续编译/烧录后可按顺序核对：

1. 五个导航入口、顶部亮度抽屉、系统页与抽屉的亮度同步；确认“异常分析”页可显示原始寄存器与中文解释。
2. 两个配置页首次读取，单选互斥，切页保留草稿，Reload/Discard 行为。
3. 数字键盘的取消、清空、上下限和步进。例如 5.005 V、0.225 A 应被拒绝。
4. 测试负载下启用控制，回读确认后对照 ADC 和仪表实测。单独验证充电与放电限流。
5. 断开芯片通信，确认错误显示且编辑被禁用；恢复通信并 Reload。
6. 改 Buck-Boost 各档位，确认其他寄存器位未被覆盖；M2 RDS(on) 与装配值匹配。
